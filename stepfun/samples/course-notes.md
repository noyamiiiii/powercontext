# 端侧 RAG 课程笔记

WebGPU 是浏览器提供的 GPU 通用计算 API。应用可以通过 `navigator.gpu.requestAdapter()` 检查适配器是否可用，并在模型加载时设置 `device: "webgpu"`。

WebGPU 不可用时，Transformers.js 可以切换到 ONNX Runtime Web 的 WASM 后端。WASM 兼容范围更广，但通常需要更长的推理时间。

FP16 使用 16 位浮点权重，适合支持 shader-f16 的 WebGPU。INT8 或 q8 使用八位权重，模型体积更小，更适合 WASM 和资源受限设备。

模型文件从 Hugging Face Hub 下载后可以进入浏览器缓存。缓存只影响模型获取，实际 embedding 计算仍由当前设备的 WebGPU 或 WASM 完成。

BGE 中文 embedding 模型使用第一个 token，也就是 CLS token，作为句子向量。文档和查询向量都应该进行 L2 归一化。

短查询用于寻找较长课程段落时，可以为查询增加检索指令。文档段落不需要添加相同指令。

HNSW 是一种近似最近邻索引。它通过图结构减少向量比较次数，适合在较大集合上执行低延迟的相似度搜索。

余弦距离比较两个向量的方向，不关心绝对长度。归一化之后，余弦相似度可以用向量点积高效计算。

全文检索依赖关键词和分词器。IK 分词器可以处理中文文本，适合课程笔记中的专业词和短语。

向量检索可以找到语义相近但措辞不同的段落。全文检索可以精确命中模型名、接口名和错误码，两者具有互补性。

RRF 是 Reciprocal Rank Fusion。它根据每条结果在全文排名和向量排名中的位置计算融合分数，不需要把两个原始分数缩放成同一范围。

新文档写入向量表后，异步构建的索引可能尚未完成。调用 `refresh_index()` 可以等待索引刷新，使刚导入的内容马上可检索。

增量导入应使用 upsert。相同文档 ID 会更新已有内容，新文档 ID 会新增记录，因此不需要删除整个知识库。

文档切块应保留来源、块编号和导入时间。元数据让用户能够核对搜索结果来自哪个文件、哪一段内容。

浏览器 Worker 可以把模型加载和 embedding 推理从主线程分离，避免界面在长任务中失去响应。

批处理可以把多条文本一次送入模型，提高吞吐。批大小过大可能增加峰值内存，因此应提供可调的 batch size。

性能测试应分别记录冷启动加载、缓存后加载、文档向量化、查询向量化、索引刷新、数据库检索和端到端延迟。
