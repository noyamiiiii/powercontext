# 午夜博物馆：会记住你的守夜员

题目：Dify「Just for Fun」，使用 Dify 1.9.2 Workflow 核心编排，seekdb 保存线索和玩家记忆，Ollama/Qwen3 本地推理，无付费 API Key 依赖。

玩法：玩家调查会说谎的展品，三条关键线索解锁真相。可以自由输入，也可以使用调查、安抚、恶作剧、出示线索等明确动作。跨 Dify 请求与会话保留玩家进度、信誉和已发现的证据；新玩家隔离。每回合由数据库规则判定状态变化，模型负责根据检索证据与历史创作叙事，不能凭生成内容修改规则状态。

流程：Start → JSON 安全编码 → seekdb 检索上下文 HTTP → 回合标识编码 → 本地模型 HTTP → seekdb 原子保存 HTTP → 格式化结果 → End，共 8 节点。Dify 同时负责输入、依赖顺序、服务错误与输出。后端分为 context / narrate / commit，不能独立替代 Dify 应用。

数据库：只在专用 midnight_museum 库建表，保存 exhibits（原创故事素材+全文索引）、players（版本号、信誉、线索）、turns（请求编号、上下文、模型输出、结果）与预备的回合上下文。提交使用行锁、版本检查和请求唯一键，抵御重试重复推进和并发旧结果覆盖。SQL 参数化，输入长度限制，不执行玩家 SQL；用户和请求标识校验。

部署：独立 Compose 项目，Dify 元数据库 PostgreSQL 与缓存 Redis 仅为平台依赖；seekdb 是游戏持久化与全文检索数据库。显式说明两种数据库分工。HTTP 节点不需要自定义插件。小模型用于可复现的 CPU 演示，允许更换 Ollama 模型。服务端失败回合不推进，错误不能伪装成模型输出。

验证：真实 Dify 导入 DSL、发布并调用工作流 API；记录节点执行、真实模型信息和 seekdb 写入/跨会话读取。另覆盖玩家隔离、重复请求、并发版本冲突、非法输入和模型不可用。提交全部源码、数据、DSL、初始化与运行脚本、证据及已知限制；不提交任何真实凭据。
