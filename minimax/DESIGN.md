# 范围与验收设计

按 2026-10-26 题面实现六项必做能力，不增加与验收无关的界面或 Agent 框架。

| 方案 | 部署与取舍 |
| --- | --- |
| 嵌入式 seekdb + PowerContext builtin + CLI（采用） | Linux 单环境可复现，组件真实参与，状态无需模型 API |
| 远程 OceanBase + PowerContext HTTP 服务 | 适合共享部署，需要额外服务与账户配置 |
| 纯文件上下文工具 | 依赖少，但不满足数据库实际参与要求 |

来源清单、任务描述与业务测试共同限定目标，所有源路径必须在工程内真实存在。
检索阶段必须从数据库取回资料，不能按任务名称返回写死的答案。
状态阶段必须经过 PowerContext 的真实写入和读取，不能以本模块自己的 JSON 文件充当状态服务。
MiniMax 调用记录必须真实生成，凭据仅从环境或显式配置文件加载。

业务例子选择单函数订单筛选；测试同时覆盖新筛选行为与原有不变行为。
开发和验收使用临时工程，保存必要快照与摘要，防止破坏用户工作区。
异常必须明确失败：空索引、缺失来源、过期来源、无模型密钥、HTTP 调用失败、越界文件修改或测试失败。

不依赖未交付的本地数据；固定版本依赖、完整源码和自动验证脚本全部位于 `minimax/`。
